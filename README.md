# MyBooks

個人の蔵書、読書状況、要約、PDF／NotebookLMなどの関連資料をまとめて管理する日本語のWebアプリです。React + TypeScript + Viteで構成し、Vercelへそのまま公開できます（分類マップのEmbeddingだけ、Vercel Function `api/embed.ts` をサーバー側で使います）。

## 起動方法

```bash
npm install
npm run dev
```

表示されたURL（通常は `http://localhost:5173`）をブラウザで開きます。本番用ファイルは `npm run build` で `dist/` に生成されます。

## 操作方法

- **本の登録**: 右上の「本を追加」からタイトル、著者、階層分類、基準月、読書状況、要約、表紙（DriveのファイルIDまたは画像URL）を入力します。タイトルだけが必須です。分類と基準月は、前回保存した本の設定が初期値になります（基準月は空欄で保存した場合は空欄のまま、初回のみ今月）。
- **表紙からの自動入力**: 編集画面の入力欄の上にある「表紙から入力」を押すと、表紙の画像の文字をAIで読み取り、**タイトル・著者・分類**を入力します。確認なしで入力し、内容が変わった項目は紫の枠と「表紙から・変更」の目印で、読み取り結果が今の内容と同じだった項目は緑の枠と「表紙と一致」の目印で示します。変わった項目の下には変更前の内容を取り消し線つきで表示し、「元に戻す」で戻せます（手で直すと目印は消えます）。読み取り中はボタンに経過秒数が出ます。通常は数秒〜十数秒で、50秒を過ぎると打ち切ってメッセージを表示します。タイトルは、カードに表示できる長さに収まるよう、表紙で一番大きな文字の書名だけを入力します（小さな文字のサブタイトルや「〜が教える」などの前置きは含めません）。ただし、同じタイトルの本がすでに登録されている場合は、前置きやサブタイトルも含めた詳しいタイトルにします（例: 「アンガーマネジメント」→「マンガでやさしくわかるアンガーマネジメント」）。著者名は、日本人の名前なら姓と名の間に半角スペースを入れて入力します（例: `田坂 広志`）。読み取った内容は保存前に確認してください。
  - タイトルが空のまま表紙画像を貼り付けた場合も、先に表紙からタイトルなどを読み取り、そのタイトルのファイル名で表紙フォルダに保存します。
  - サーバー側の `/api/cover-info`（Vercel Function）で、分類マップと同じ `GEMINI_API_KEY`（または `OPENAI_API_KEY`）を使います。モデルは既定で `gemini-flash-latest`（常に最新のGemini Flash。OpenAIは `gpt-4.1-mini`）で、見つからない場合は `gemini-flash-lite-latest` などを順に試します。変える場合は環境変数 `VISION_MODEL` を設定します。Drive上の表紙を読むときは、表紙フォルダの共有設定が「リンクを知っている全員」になっている必要があります。
- **要約のコピー**: 要約を入力した本は、カードの著者名の横に小さなコピーボタンが出ます。押すと要約をクリップボードにコピーします。
- **確認・編集・削除**: カードまたは表の行を押すと詳細画面が開きます。変更後は「変更を保存」、削除するときは左下の「削除」を押します。著者名の全角スペースや連続した空白は、保存時に半角スペース1つにそろえます。
- **類似する本・同じ著者の本**: 詳細画面の上部のタブで切り替えます。
  - 「類似する本」は、分類マップと同じEmbeddingを使い、タイトルと要約の内容が近い本を類似度の高い順に10冊表示します。まだ計算されていない本（追加・要約の変更の直後など）は「内容の近さを計算する」を押すと計算します（Embedding APIの設定が必要。下記「本の分類マップ」参照）。
  - 「同じ著者の本」は、著者が同じ本をすべて表示します。空白・全角半角の違いや「著」「編」「監修」などの表記は無視し、「、」などで区切った共著者のいずれかが同じなら同じ著者とみなします。
  - 一覧の本を押すと、その本の詳細画面に切り替わります（開いていた本の変更は保存されます）。
- **関連資料**: 詳細画面には「全ページスキャン」「インフォグラフィック」「音声解説」「動画解説」「GeminiNotebookスライド」の欄が最初から用意されているので、URLを貼るだけで登録できます（URL欄の右端のクリップボードボタンを押すと、コピーしたURLをそのまま入れられます。URL欄にはURL以外の文字は入力できません）。表示名は候補から選ぶか自由に入力でき、「リンクを追加」で欄を増やせます。左端のつまみ（⋮⋮）をドラッグ（またはつまみを選んで↑↓キー）で順番を変えられます。URLが空の欄は保存されません。カードには先頭から6件までのリンクが表示され、編集画面を開かずにクリックで開けます。
- **全ページスキャン**: 「全ページスキャン」の欄は表示名を変更できず、編集画面・カードとも常に関連リンクの先頭に表示します（URLは変更・空欄にできます）。
  - 要約欄の右上の「全ページスキャンから要約」を押すと、全ページスキャンのリンク先（DriveのPDFなど）をAI（Gemini）が読んで、300〜400字程度の要約を作ります。今の要約があるときは置き換えるか確認します。ページ数によって数十秒〜数分かかり、ボタンに経過秒数が表示されます。**作成中に詳細画面を閉じても処理は続きます**（カードに「要約作成中」と表示）。閉じている間に終わると、その本の要約として自動で保存し、画面下にお知らせを出します（失敗したときもお知らせします）。開いている間に終わった場合は、要約欄に入るので確認してから保存します。
  - Driveのファイルは、初めて要約を作るときだけGoogleの許可画面で「Driveのファイルの参照」（読み取り専用の `drive.readonly`）を許可します。2回目以降は本ごとの許可や選択は不要で、ボタンを押すだけで要約を作れます（1時間ごとのログインの更新で一瞬ポップアップが開くことがあります）。この権限は要約のためにスキャンを読むときだけ使い、書き込みはしません。
  - 読み取り専用の権限を許可しなかった場合は、従来どおりGoogleの選択画面でそのファイルを選んでアクセスを許可します（本ごとに初回のみ）。「リンクを知っている全員」に共有されたファイルは、許可なしでも読めます。
  - サーバー側の `/api/summarize-scan`（Vercel Function）で `GEMINI_API_KEY` を使います（OpenAIのキーでは使えません）。実行時間の上限は `vercel.json` で300秒にしています（VercelのFluid computeが有効なプロジェクトで使えます）。モデルを変える場合は `SUMMARY_MODEL` を設定します。
- **検索・絞り込み**: 検索欄はタイトル、著者、分類（親分類を含む）、要約を横断検索します。分類と読書状況のプルダウンも併用できます。
- **意味検索**: 検索欄の右端の「意味検索」がオンのとき、単語や文章（例：「仕事の生産性を上げたい」「人はなぜ争うのか」）から、タイトルや要約にその言葉が含まれていなくても意味の近い本を探して、近い順に並べます（下記「意味検索」参照）。分類・読書状況の絞り込みも併用できます。
- **表示切替**: 「カード」「リスト」「マップ」で、表紙中心の表示、比較しやすい表形式、本の分類マップを切り替えます。
- **本の分類マップ**: 「マップ」では、タイトルと要約の内容が近い本ほど近くに並ぶ散布図を表示します（下記「本の分類マップ」参照）。
- **空の状態**: 全データを削除した場合も、最初の本を追加する案内が表示されます。

## 本の分類マップ

「マップ」を押すと、登録した本を1冊1点で並べた2次元マップを表示します。

- **位置**＝タイトル＋要約から判断した内容の近さ（要約が空の本はタイトルだけで判断。タイトルのない本は対象外）。縦軸・横軸そのものに意味はありません。
- **色**＝既存の分類（A〜Gの親分類）。上部の凡例を押すと、その分類で絞り込みます。
- **操作**: ホイール（またはピンチ）でズーム、ドラッグで移動、右上のボタンで拡大・縮小・全体表示。点にマウスを乗せると表紙・タイトル・要約（先頭100文字）・分類・読書状況が出て、クリックで「本の詳細・編集」を開きます（スマートフォンは1回目のタップで内容表示、もう一度タップで開く）。
- **検索・絞り込み**: 上の検索欄・分類・読書状況の絞り込みがそのまま使えます。条件に合う本は色付き、合わない本は薄い灰色で表示し、表示中の点が少ないときはタイトルも表示します。

### 仕組み

1. タイトルと要約をつなげたテキストを、サーバー側の `/api/embed`（Vercel Function）でEmbedding（256次元のベクトル）にします。APIキーはサーバーの環境変数だけで扱い、ブラウザには渡しません。
2. ベクトルをブラウザ内（Web Worker）でUMAPにかけ、2次元の座標にします。3000冊でも数秒です。
3. ベクトルと座標は、ブラウザ（IndexedDB）と、Google Driveの保存先フォルダの `MyBooks-map.json` に保存して再利用します。本棚データの `MyBooks-library.json` とは別ファイルなので、本棚の保存には影響しません。
4. 次回からは、**タイトルか要約が変わった本・追加した本だけ**Embeddingを計算します。数冊の追加・変更なら、内容の近い本のそばに配置するだけで、全体の配置は変えません。前回の全体配置から15%（最低20冊）を超える本が追加・変更されたとき、または「配置を再計算」を押したときに、UMAPで全体を配置し直します。

### 初期設定（Embedding APIキー）

1. [Google AI Studio](https://aistudio.google.com/apikey) でGemini APIのAPIキーを作成します（OpenAIを使う場合はOpenAIのAPIキー）。
2. Vercelのプロジェクトで **Settings → Environment Variables** に `GEMINI_API_KEY`（または `OPENAI_API_KEY`）を追加し、再デプロイします（表紙からの自動入力にも同じキーを使います）。**`VITE_` を付けないでください**（付けるとブラウザに公開されます）。
   - モデルは既定で `gemini-embedding-001`（OpenAIは `text-embedding-3-small`）です。変える場合は `EMBEDDING_MODEL` を設定します。モデルを変えると、全冊のEmbeddingが一度だけ再計算されます。
3. `VITE_GOOGLE_CLIENT_ID` が設定されている場合、`/api/embed` はこのアプリのGoogleログインのトークンを確認し、それ以外からの呼び出しを拒否します。マップで新しい本を計算するときは「Driveに接続」した状態で開いてください（計算済みのマップは未接続でも表示できます）。
4. ローカルでは `.env.local` に `GEMINI_API_KEY=...` を書いて `npm run dev` を起動すると、開発サーバーが `/api/embed` も処理します。

## 意味検索（セマンティック検索）

キーワードの一致ではなく「意味の近さ」で本を探します。分類マップとは別のデータ（ベクトル）を使います。

- **検索用テキスト**: 本ごとに「タイトル・著者・分類（親 / 子）・要約」をつなげたものです。タイトルのない本は対象外です。
- **書籍側のEmbedding**: 検索用テキストを `/api/embed`（Gemini の `RETRIEVAL_DOCUMENT`、768次元）でベクトルにし、ブラウザ（IndexedDB）と Google Drive の保存先フォルダの `MyBooks-search.json` に保存します。
  - 生成するタイミングは、アプリを開いたとき（初回は全冊。100冊ずつまとめて送ります）と、本の追加・編集・CSV/JSONの読み込みのあとです。どちらも**検索用テキストが変わった本だけ**を送り、変わっていない本はAPIを呼びません。別の端末で計算済みのデータは Drive から読み込んで使います。
  - Google Drive連携を設定している場合は、ログイン（接続）してから計算します。
- **検索の流れ**: 入力が止まって0.5秒後に、検索文だけを `/api/embed`（`RETRIEVAL_QUERY`）でベクトルにし、保存済みの本のベクトルとのコサイン類似度（semanticScore）を計算します。同じ検索文はブラウザが覚えているので、APIを再び呼びません。
- **並び順（ハイブリッド検索）**: `finalScore = semanticScore × 0.8 + keywordScore × 0.2`。keywordScore はタイトル完全一致 1.0、タイトル部分一致 0.85、著者一致 0.7、分類・要約・基準月の一致 0.5 です。
  - キーワードが一致した本（従来の検索結果）はすべて残り、そこに意味の近い本（最も近い本との差が0.12以内、少なくとも10冊・最大100冊）が加わります。
  - 1文字の検索や基準月（YYYY-MM）はキーワード検索だけで行います。「意味検索」をオフにすると、従来どおりの部分一致検索になります。
- **関連度の表示（開発確認用）**: 検索中に表示される「関連度を表示」にチェックを入れる（またはURLに `?debug` を付けて開く）と、各本に「関連度 0.82」（finalScore。マウスを乗せると意味・キーワードの内訳）を表示します。
- **作り直す（再Embedding）**: 「関連度を表示」がオンのときに出る「作り直す」で、全冊のEmbeddingを計算し直します。`EMBEDDING_MODEL` やAPIキーの種類（Gemini / OpenAI）を変えた場合は、モデルの違いを検出して自動で全冊を計算し直します。
- **環境変数**: 分類マップと同じ `GEMINI_API_KEY`（または `OPENAI_API_KEY`）を Vercel の環境変数に設定します（`EMBEDDING_MODEL` は任意）。APIキーはサーバー側だけで使い、ブラウザやGitHubには出ません。

## CSVからのデータ移行

「保存・バックアップ」→「データを読み込む」からUTF-8のCSVを選びます。CSVは既存データへ**追加**されます。列名は次のとおりです。

```csv
タイトル,著者,分類,基準月,読書状況,要約,表紙画像URL,関連リンク
なっとくする物理数学,都筑 卓司,D-1: 数学,2014-05,読了,復習用,https://example.com/cover.jpg,インフォグラフィック::https://drive.google.com/...|音声解説::https://drive.google.com/...
```

「関連リンク」列は `表示名::URL` を `|` で区切って並べます（以前の `種類::表示名::URL` 形式も読み込めます）。CSVの「表紙画像URL」列には、DriveのファイルID・共有リンク・画像URLのどれを書いても構いません。

### CSV取り込み時の注意

- 文字コードは **UTF-8**、1行目は上記の列名にしてください。タイトル以外は空欄でも取り込めます。
- 分類名はアプリ内の名称（例: `D-1: 数学`）と完全一致させます。一致しない場合は `D-1: 数学` になります。
- 要約の列は、以前の列名 `メモ` でも取り込めます。
- 基準月は `YYYY-MM`、読書状況は `未読`／`読書中`／`読了` のいずれかです。
- カンマ、改行、ダブルクォートを含む値はCSVの標準に従ってダブルクォートで囲みます。現在の簡易取込では、セル内改行には対応していません。
- 関連リンクは `表示名::URL` の形です。複数は半角 `|` で区切ります。
- 表紙は画像ファイル自体ではなく、ブラウザから取得できる `https://` の画像URLを指定してください。
- 表紙画像はGoogle Driveの表紙フォルダ（[MyBooks表紙フォルダ](https://drive.google.com/drive/folders/1nQ70ASmx51gP530IRPGp1ZZQnkxwp9vt)）に置き、**ファイルID**で参照します。
  - 本の編集画面で、コピーした画像を**クリップボードから貼り付け**できます。表紙プレビュー枠のクリック、「画像を貼り付け」ボタン、または Ctrl+V（⌘+V）で、画像を表紙フォルダに「タイトル名.png」などのファイル名で保存し、そのファイルIDを表紙に設定します（先にタイトルを入力してください）。保存した画像は「リンクを知っている全員が閲覧可」に設定されます。初回のみ、Googleの選択画面で表紙フォルダを選んでアクセスを許可します。
  - ファイル名はタイトルと同じですが、本との結び付けはファイルIDで行うため、同じ名前のファイルがあっても取り違えません。
  - 本の編集画面の「Driveから選ぶ」で、表紙フォルダの画像を一覧から選べます（Googleへのログインが必要です）。
  - 共有リンク（`https://drive.google.com/file/d/<ファイルID>/view?usp=sharing` など）を貼り付けた場合も、自動でファイルIDに変換して保存します。以前に保存した共有リンクも、読み込み時にIDへそろえます。
  - アプリに表示するには、表紙フォルダの共有設定を「リンクを知っている全員（閲覧者）」にしてください（フォルダ内の画像に引き継がれます）。表示できない場合はプレースホルダーが表示されます。
  - Drive以外の `https://` の画像URLもそのまま使えます。
- まず少数行で試し、問題がなければ全件を取り込むことを推奨します。重複判定は行わないため、同じCSVを複数回読み込むと重複します。

## 保存とGoogle Drive

### Google Driveへの自動保存（推奨）

Googleアカウントでログインすると、本棚のデータをGoogle Driveの [MyBooksフォルダ](https://drive.google.com/drive/folders/12T2RtZHu_lpq8_zVeExmYHiAh_v7cKIW)（マイドライブ > WebAppsData > MyBooks）内の `MyBooks-library.json` に自動保存します。別のPCやスマートフォンからログインしても同じデータを使えます。

1. ヘッダー右上の「Driveに接続」（スマートフォンでは雲のアイコン）を押し、「Googleでログインして接続」を選びます。
2. 初回はGoogleの許可画面が出るので、MyBooksにGoogle Driveへのアクセスを許可します。
   - 許可の範囲は `drive.file` です。**このアプリが作成したファイルにだけ**アクセスでき、ほかのDriveのファイルは読み書きしません（「全ページスキャンから要約」を使うときだけ、スキャンを読むための読み取り専用の権限を追加で求めます）。
3. 初回のみ「フォルダの許可が必要」と表示されます。「MyBooksフォルダを許可」を押し、Googleの選択画面でMyBooksフォルダを選んで「選択」を押してください。これで、アプリがこのフォルダにファイルを作れるようになります。
4. 以降は本を追加・編集するたびに、自動でDriveに保存されます。ヘッダーのボタンで状態（保存待ち・同期中・Drive保存済み）が分かります。

補足：

- 保存先フォルダと保存ファイルは**名前ではなくID**で扱います。フォルダは作成せず、フォルダ内に `MyBooks-library.json` が無いときだけ1回作成します。以後はそのファイルIDを使って更新するため、同じ名前のファイルやフォルダが増えることはありません（フォルダ内に同名ファイルが複数あった場合も、最初に作られたものだけを使います）。

- ページを開くと、Driveの最新データを自動で読み込みます（同じタブでログイン済みの場合）。ブラウザを閉じたあとや、ログインから約1時間が経ったあとは、もう一度「Driveに接続」を押してください。
- このブラウザに未保存の変更があり、別の端末でDriveのデータも更新されていた場合は、どちらのデータを残すかを確認するダイアログが出ます。
- Driveに接続していない間も、データはこれまでどおりブラウザ（`localStorage`）に保存されます。

### JSONバックアップ

「保存・バックアップ」の「バックアップを書き出す」で、日付付きのJSONファイルをダウンロードできます。復元するときは「データを読み込む」でJSONを選びます。JSONの読み込みは現在のデータを**置き換えます**（Driveに接続中は、読み込んだ内容がDriveにも保存されます）。大きな編集の前などに、世代ごとのバックアップとして保管してください。

### Google Drive連携の初期設定（最初に1回だけ）

Driveに保存するには、Google CloudでOAuthクライアントIDを作成し、環境変数 `VITE_GOOGLE_CLIENT_ID` に設定します。未設定の場合、Drive連携は表示されず、ブラウザ内への保存だけになります。

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成します（既存のものでも可）。
2. **APIとサービス → ライブラリ** で「Google Drive API」を有効にします。
3. **APIとサービス → OAuth同意画面**（Google Auth Platform）を設定します。
   - ユーザーの種類は「外部」、アプリ名は `MyBooks` など。
   - **データアクセス（スコープ）** に `https://www.googleapis.com/auth/drive.file` を追加します。全ページスキャンからの要約を使う場合は、`https://www.googleapis.com/auth/drive.readonly`（制限付きスコープ）も追加します。公開ステータスが「テスト」のままなら、Googleの審査なしでテストユーザーが使えます（許可画面に「Googleで確認されていません」と出たら「続行」を押します）。
   - 公開ステータスが「テスト」の間は、**テストユーザー**に自分のGoogleアカウントを追加します（テストユーザー以外はログインできません）。
4. **APIとサービス → 認証情報 → 認証情報を作成 → OAuthクライアントID** を選びます。
   - アプリケーションの種類：**ウェブアプリケーション**
   - 承認済みのJavaScript生成元：公開URL（例：`https://my-books-ashen.vercel.app`）と、ローカル開発用の `http://localhost:5173`
   - リダイレクトURIは不要です。
5. 作成された「クライアントID」（`xxxx.apps.googleusercontent.com`）をコピーします。クライアントシークレットは使いません。
6. Vercelのプロジェクトで **Settings → Environment Variables** に `VITE_GOOGLE_CLIENT_ID` を追加し、値にクライアントIDを貼り付けます。その後、**Deployments** から再デプロイします（環境変数はビルド時に埋め込まれるため、再デプロイが必要です）。
7. Google Picker（保存先フォルダの許可と「Driveから選ぶ」）のために、**APIとサービス → ライブラリ** で「Google Picker API」も有効にし、**認証情報 → 認証情報を作成 → APIキー** でAPIキーを作成します。APIキーには「ウェブサイトの制限」で公開URLと `http://localhost:5173/*` を、「APIの制限」で Google Picker API を設定してください。作成したキーをVercelの環境変数 `VITE_GOOGLE_API_KEY` に設定します。
   - あわせて、Google Cloudの**プロジェクト番号**（ダッシュボードの「プロジェクト情報」にある数字）を環境変数 `VITE_GOOGLE_APP_ID` に設定し、再デプロイします。保存先フォルダの許可に必要です。
   - `VITE_GOOGLE_API_KEY` が未設定の場合、「Driveから選ぶ」ボタンは表示されません（IDや共有リンクの貼り付けは使えます）。
8. 保存先フォルダを変える場合は `VITE_DRIVE_DATA_FOLDER_ID`、表紙フォルダを変える場合は `VITE_DRIVE_COVER_FOLDER_ID` にフォルダIDを設定します（未設定時は上記のフォルダ）。
9. ローカルで試す場合は、`.env.example` を `.env.local` にコピーしてクライアントIDを書き込みます。

## Vercelへの公開

1. このリポジトリをGitHub、GitLab、またはBitbucketへpushします。
2. [Vercel](https://vercel.com/) のダッシュボードで **Add New → Project** を選び、リポジトリをImportします。
3. Framework Presetは `Vite`（通常は自動検出）、Build Commandは `npm run build`、Output Directoryは `dist` にします。
4. Google Drive保存を使う場合は、環境変数 `VITE_GOOGLE_CLIENT_ID` を設定します（上記「Google Drive連携の初期設定」参照）。**Deploy** を押します。
5. 公開URLで本を1冊登録し、再読み込み後にも残ることと、JSONの書き出し・読み込みを確認します。

> データは公開URLごと・ブラウザごとのローカル保存です。Vercelへの再デプロイでは消えませんが、別端末には同期されません。共有データベースを持たず個人利用を優先した構成です。
