# 本とYouTubeの知識ライブラリ

既存の本・Google Drive保存・MyBooksブランドを維持し、高評価したYouTube動画を同じ画面で検索・再発見できるように拡張しています。

## 使い方

1. 上部の「本 / YouTube / すべて」で表示対象を切り替えます。初期表示は従来どおり本です。
2. YouTube画面の「YouTubeと同期」で、本人の高評価動画を取得します。初回はGoogleの追加許可が必要です。複数ページを取得し、既存のvideoIdはスキップします。同期は追記方式です。高評価を外した動画・非公開になった動画を自動削除しません。公開APIで返される動画のみ取得でき、高評価日時・視聴履歴・他ユーザーの高評価は取得しません。
3. 取得時には動画AI解析を実行しません。動画がある場合、空の検索語での自動Embedding更新も延期し、意味検索の入力・AI推薦・マップの利用時に必要なベクトルを作ります。これらのEmbedding APIにも料金が発生します。「この動画をAI解析」「未解析動画を一括解析」「選択動画のみ解析」から開始します。選択はカードのチェックボックスで行います。一括処理は未解析だけを対象に、複数件なら件数とAPI料金の確認を表示します。
4. 解析は1件ずつ行い、成功ごとに保存します。認証・課金・利用上限・未設定では停止します。停止・失敗・再読み込み後も未解析の動画だけを再実行できます。解析済みの動画は再解析しません。
5. 動画カード・リストから詳細を開けます。要約、重要ポイント、既存分類の親・子、タグ、おすすめ対象、2軸の目安を表示します。YouTubeへのリンクは別タブで開きます。
6. 「すべて」で意味検索・AIセレクトを使うと本と動画を横断します。「本」のAI選書は維持し、YouTubeではAI選動画と表示します。推薦理由、質問との関係、得られること、おすすめ度を表示します。候補には両方の媒体を残し、AIは関連性を優先して最大5件を選びます。必ず一定比率の結果になるわけではありません。
7. マップは共通のEmbedding/UMAP空間に配置し、本は丸、動画は三角で表示します。元のマップ同様、2軸の表示は傾向の目安です。AIが付けた0〜100の数値をUMAP座標とはみなしません。
8. 「興味分析」で本だけ・YouTubeだけ・両方を切り替えます。分類割合は全件集計で、AIには分類集計と媒体ごと最大30件の均等抽出サンプルを送ります。本と動画の選び方の違いを説明し、同じ入力のAI結果は最大10件までブラウザで再利用します。登録・高評価は読了・視聴済みを意味しません。
9. 設定（歯車）のYouTube連携で、接続状態、動画件数、最終同期、解析済み件数、動画のDrive保存状態を確認できます。

## Google Cloudの設定

既存のGoogle OAuthクライアントを使用します。APIキーだけでは本人の高評価動画を取得できません。今回の機能にサーバー用の `YOUTUBE_API_KEY` は不要です（この変数は従来の著者プロフィール用です）。

- Google Cloudで **YouTube Data API v3** を有効にします。
- OAuth同意画面のデータアクセスに `https://www.googleapis.com/auth/youtube.readonly` を追加します。テスト中の場合は自分のGoogleアカウントをテストユーザーに追加します。
- `VITE_GOOGLE_CLIENT_ID` に既存のOAuthクライアントIDを設定します。
- 承認済みのJavaScript生成元に、実際に利用するアプリの生成元を追加します。ローカル開発なら `http://localhost:5173` などです。テスト用ポートを実運用の設定に追加する必要はありません。
- Driveのフォルダ許可は従来のGoogle Picker設定を再利用します。`VITE_GOOGLE_API_KEY`、`VITE_GOOGLE_APP_ID` が必要です。
- サーバー側ログイン更新を使う場合は既存の `GOOGLE_CLIENT_SECRET` / `SESSION_SECRET` を利用します。YouTube権限は同期操作から追加します。未設定ならセッション中のGISアクセストークンを使用します。

## AIと情報の範囲

既存のサーバー側 `GEMINI_API_KEY`、または対応機能で `OPENAI_API_KEY` を利用します。APIキーをブラウザに渡しません。`YOUTUBE_MODEL` は動画解析、`INTEREST_MODEL` は興味分析のモデルを上書きします。未指定なら既存モデル設定と既定モデルにフォールバックします。推薦は既存 `PICK_MODEL`、意味検索とマップは既存 `EMBEDDING_MODEL` を使います。

現段階の解析入力は **タイトル・概要欄・チャンネル名** です。動画の本編や字幕を確認した要約ではありません。情報の薄い動画は内容を推測しないようAIへ指示し、詳細画面にも解析範囲を表示します。将来の字幕入力用に `transcript` フィールドを予約していますが、字幕の取得・スクレイピングは実装していません。

2軸スコアは具体=0／抽象=100、技術=0／社会=100です。既存の本には数値スコアがないため、興味分析で本と動画の数値比較を捏造しません。

利用環境で必要になる通信先はGoogle認証の `accounts.google.com`、`oauth2.googleapis.com`、Google APIの `www.googleapis.com`、Pickerの `apis.google.com`、サムネイルの `i.ytimg.com`、Geminiの `generativelanguage.googleapis.com` またはOpenAIの `api.openai.com` です。制限付きネットワークでは必要な宛先を既存許可リストに追加してください。

## 保存と後方互換性

- 既存の `Book`、localStorage `mybooks-library-v1`、Drive `MyBooks-library.json` の形式を維持します。
- 動画は `YouTubeVideo` 型、localStorage `mybooks-youtube-v1`、Drive `MyBooks-youtube.json` の別JSONに保存します。サムネイル画像そのものは保存せずURLだけ保存します。
- Drive同期フックを保存先アダプターで共通化します。動画の端末間同期はvideoIdの和集合を保持し、同じ動画の更新は新しいupdatedAtを採用します。本の競合確認は維持します。
- 表示・検索・推薦・マップでは読み取り専用の `LibraryItem` アダプターを利用します。動画を本の保存ファイルへ書き戻しません。動画IDには `youtube:` を付けて区別します。
- JSONバックアップはversion 2で `books` と `videos` を含めます。古い本のみのJSONも読み込め、その場合は動画を変更しません。version 2の動画データは形式を検証してから本の保存を更新します。CSVは従来どおり本にのみ適用します。
- 意味検索・推薦のインデックスは全ライブラリを共有します。分類マップの再計算も全ライブラリで行い、本のみの類似表示を使っても動画キャッシュを削除しません。

## 検証

```sh
npm run build
npm run lint
npm test
npm run test:browser
```

`npm test` はネットワークを模擬してデータ互換性、同期・Drive統合、出力検証、検索・候補選定、興味集計、APIの入力・認証エラーを検証します。

`npm run test:browser` は専用のViteサーバーをポート5175で起動し、テスト用の独立ブラウザでGoogle／YouTube／AI／Driveの応答を模擬します。テスト後にサーバーを停止します。本物のGoogleアカウントやAPIキーは使いません。PlaywrightのChromiumが必要です（`npx playwright install chromium`）。システムChromiumがある場合は自動利用し、別パスの場合は `CHROMIUM_PATH` で指定できます。

実Googleアカウントでの同意、実YouTube API、実AIモデルの要約品質は、実際の設定をした環境で別途確認してください。模擬テストの成功は実サービスへの接続確認を意味しません。
